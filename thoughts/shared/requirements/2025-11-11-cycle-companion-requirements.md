# Cycle Companion Requirements (EARS)

Scope: This document translates the Step 2 narrative in `thoughts/shared/features/2025-11-11-cycle-companion-feature.md` into EARS-formatted requirements for the React Native iOS Cycle Companion that ingests Apple Health menstrual data and persists to Supabase.

## UI & Interaction (React Native Surfaces)
1. Event-driven: When a user completes Sign in with Apple, the system shall present `CompanionIntroScreen` describing the read-only social model and prompting for HealthKit permissions within the same flow (Experience Narrative #1; New Joiner). Acceptance Evidence: Detox onboarding test verifies the intro copy appears immediately post-auth and that the permission CTA invokes `app/services/healthkit/permissions.ts`.
2. Event-driven: When a user denies the HealthKit prompt, the system shall display inline education plus a retry button on `CompanionIntroScreen` without leaving the app (Experience Narrative #1). Acceptance Evidence: Snapshot test of the denial state plus Detox automation that simulates a permission rejection and confirms the retry CTA calls the permission handler again.
3. Ubiquitous: The Feed screen shall render `DailySummaryCard` at the top, summarizing the latest synced phase, window, and any PMS/symptom data pulled from Apple Health, with visible timestamps (Experience Narrative #2; Reflective Tracker). Acceptance Evidence: Jest component test asserting props render phase + symptom pills and E2E test validating the card is first in the feed list.
4. Ubiquitous: `DailySummaryCard` shall expose CTA buttons that deep-link to `FriendSyncScreen` and the reactions composer so users can immediately boop or review sync scores (Experience Narrative #2; Social Supporter). Acceptance Evidence: React Navigation test confirming the CTA routes plus Detox tap test verifying navigation destinations.
5. Event-driven: When a friend’s state transitions into PMS or menstruation (based on synced data), the system shall badge `NotificationsBell.tsx` and prefill the boop suggestion before opening that friend’s feed entry (Experience Narrative #3; Social Supporter). Acceptance Evidence: Integration test that mocks a friend state change and asserts badge props + navigation payload.
6. Ubiquitous: `FriendSyncScreen` shall display overlap timelines, the dummy sync score, and recommendation chips while restricting actions to existing controls (boop, react, manage friend) (Experience Narrative #4). Acceptance Evidence: Storybook/RTL test confirming required widgets render plus Detox flow covering boop from the sync screen.
7. Ubiquitous: `ProfileScreen` shall show the user’s current phase and provide friend filters grouped by phase, with tap targets that open the corresponding `FriendSyncScreen` or return to `DailySummaryCard` (Experience Narrative #5). Acceptance Evidence: RTL test verifying filter buttons render correct counts; navigation test confirming deep links.
8. State-driven: While Supabase or HealthKit is offline, `DailySummaryCard` shall surface the last synced snapshot, show a “Retry sync” banner, and keep boop/reaction CTAs enabled (Experience Narrative #6). Acceptance Evidence: Offline simulation test ensuring cached data renders and queued actions remain tappable; unit test verifying banner visibility when sync status === offline.

## Data & State (Apple Health, Supabase, Local Cache)
1. Ubiquitous: The system shall read menstrual flow and prediction samples exclusively via `@kingstinct/react-native-healthkit`, never writing data back to Apple Health (Constraints: Apple Health Permissions). Acceptance Evidence: Module-level unit test enforcing read-only method usage and code lint rule preventing write APIs.
2. Event-driven: When new HealthKit samples are retrieved, the system shall normalize them into domain models, persist them to local SQLite (`app/storage/health.db`), and upsert to Supabase tables within the same sync transaction (Experience Narrative #2). Acceptance Evidence: Jest test around the sync service verifying dual persistence; instrumentation log checked during QA run.
3. Event-driven: After each successful sync, the system shall refresh `DailySummaryCard` data and invalidate related React Query caches so the feed reflects the freshest Apple Health state (Experience Narrative #2). Acceptance Evidence: Unit test for the sync hook ensuring cache invalidation; Detox test confirming the UI updates after pulling new data.
4. Event-driven: When the system detects a friend entering PMS/menstruation, it shall create a notification record plus metadata for the prefilled boop suggestion, stored in Supabase for delivery to the client (Experience Narrative #3). Acceptance Evidence: Supabase function test confirming notification rows are emitted with correct payload; client test verifying the badge reads that payload.
5. State-driven: While the device is offline, boop and reaction actions shall enqueue locally and replay against Supabase once connectivity returns, maintaining original timestamps (Experience Narrative #6). Acceptance Evidence: Offline integration test showing queued events in SQLite and replay verification on reconnection.
6. State-driven: If more than 24 hours pass without a new HealthKit sync, the system shall hide `DailySummaryCard` and replace it with an empty-state prompt instructing users to refresh permissions (Constraints: Data Freshness Window). Acceptance Evidence: Time-travel unit test proving the TTL logic; UI test verifying the empty state renders after TTL expiry.
7. State-driven: Friend-specific insights (overlap timelines, recommendations) shall only appear when both users have explicit sharing consent flags stored in Supabase (Constraints: Supabase Privacy). Acceptance Evidence: Supabase RLS test verifying queries filter on consent flag; UI test confirming the section hides when consent is false.

## Privacy & Compliance
1. Ubiquitous: All HealthKit permission copy shall explicitly state that InSync only reads menstrual data and does not write anything back, matching Apple’s developer guidelines (Constraints: Apple Health Permissions). Acceptance Evidence: Content review checklist plus screenshot artefact in release QA.
2. Ubiquitous: The app shall require Sign in with Apple as the primary authentication method before any Cycle Companion data is shown (Constraints: Regulatory Requirements). Acceptance Evidence: Auth flow test ensuring unauthenticated users are redirected to SIWA and cannot access the feed.
3. Ubiquitous: Supabase row-level security policies shall ensure users can access only their own data plus that of mutually accepted friends, including Cycle Companion summaries (Constraints: Supabase Privacy & Residency). Acceptance Evidence: Supabase policy test suite proving unauthorized selects are rejected; penetration test results attached to release notes.
4. Ubiquitous: Each sensitive summary shall include a persistent “Learn more” link to `ResourcesSheet.tsx`, avoiding medical promises while providing guidance (Experience Narrative #7). Acceptance Evidence: Snapshot test ensuring the link renders; content QA sign-off on copy.
5. Optional: Where a deployment region outside the default US is mandated, the system shall allow configuring Supabase projects in alternative regions before provisioning to satisfy data residency requirements (Constraints: Supabase Privacy & Residency). Acceptance Evidence: Infrastructure checklist verifying region parameterization plus environment smoke test from a non-US project.
6. Ubiquitous: Client and server logs shall exclude PHI beyond the Apple Health data already ingested, redacting symptom descriptions when stored outside Supabase (Constraints: Privacy Guardrails). Acceptance Evidence: Log inspection script confirming redaction plus automated unit tests for the logger utility.
