# Bugs

Known bugs to fix. This is for **open** bugs; problems we already diagnosed and fixed during setup are recorded in [TROUBLESHOOTING.md](TROUBLESHOOTING.md), and feature work lives in [FEATURES.md](FEATURES.md).

## Open

### Found in a full-codebase review (2026-07-27)

- [ ] **Consent is auto-granted on friend-accept — the advertised "explicit mutual consent" isn't what happens (privacy honesty).** `ensure_friend_sharing` sets `has_shared = true` for **both** directions unconditionally, and it runs on every friend-accept *and* on every `FriendsScreen.loadFriends()`. So the instant two people are friends they can each read the other's cycle snapshot/events — there's no separate opt-in. The "Consent Needed" card in `FriendSyncScreen` is effectively unreachable in the normal flow. This contradicts LEARNINGS.md ("a friend sees your cycle data only if `has_shared=true` on **both** sides… a Consent Needed state until consent is mutual"). RLS itself is sound (non-friends see nothing) — this is a *consent-model / product-honesty* issue, not a leak. Decide the intended model and make code + copy + docs agree. Origin: `supabase/migrations/20251230032000_friend-sharing-helpers.sql`, `friendRequests.respondToFriendRequest`, `FriendsScreen.loadFriends`.
- [ ] **No way to revoke cycle-data sharing while staying friends; the toggle is dead code.** `setFriendSharing(friendId, hasShared)` exists in `friendSharing.ts:44` but is **never called anywhere in the app** — there's no UI to turn sharing off. Even if there were, the next `loadFriends()` would call `ensure_friend_sharing` and force `has_shared` back to `true`, so revocation wouldn't stick. Today the only way to stop sharing is to remove the friend entirely. Pairs with the consent-model bug above.
- [ ] **Duplicate migration files (schema-history hygiene).** ~8 pairs of near-identical migrations exist with underscore-vs-hyphen names, e.g. `20260124162946_event_reactions.sql` + `20260127120000_event-reactions.sql`; also duplicated: `friend_recommendations`, `remove_friend`, `boops_select_events`, `cycle_guidance`, `schedule_cycle_guidance`, `friend_request_email_blind`, `sync_score`. They're idempotent (`create or replace` / `drop policy if exists`), so a fresh DB survives running both — but the history is confusing and error-prone, and it signals the local migration set diverged from what was applied by hand. Reconcile (keep one of each, or document why both exist).
- [ ] **Double-tap "like" removes an existing reaction instead of always liking.** Double-tapping a post/event calls `handleReaction(target, quickReactions[0])`, and `handleReaction` *toggles* — so double-tapping something you already reacted to with the default emoji **removes** the reaction. Instagram-style double-tap should always add/keep a like, never un-like. Origin: `HomeScreen.tsx` `handlePostPress`/`handleEventPress` → `handleReaction`.
- [ ] **`loadFeed` is a long serial await-waterfall (perf).** Feed load/refocus runs 8+ dependent `await`s back-to-back (posts → post reactions → post boops → my post boops → events → event reactions → event boops → my event boops → profiles). The independent reads should run with `Promise.all`; today the feed is as slow as the sum of every round-trip, which will feel sluggish on real networks. Origin: `HomeScreen.tsx` `loadFeed`.
- [ ] **`npm test` is red by default — `architecture-sync.test.ts` hard-fails without `OPENAI_API_KEY`.** The suite is 32/33 green; the one failure is an LLM-eval test that `throw`s when the key is absent (by design — see its header comment) instead of `test.skip`-ping. That means every contributor without an OpenAI key sees a failing `npm test`, which directly undercuts the CLAUDE.md rule "run `npm test` and confirm it passes after every change." Fix: skip (don't fail) when the key is missing outside CI — e.g. `(openaiApiKey ? test : test.skip)(…)`. Origin: `__tests__/architecture-sync.test.ts:243`.
- [ ] **Test suite is slow + hits the network (integration tests mislabeled as unit).** A full run took ~500s; the `services/supabase/*` tests take ~150s each and load `.env`, i.e. they exercise real Supabase rather than mocks. This is why `npm test` times out in constrained environments and makes the "run tests every change" rule painful. Consider splitting fast unit tests (domain/`syncScore`/reactions) from networked integration tests behind a separate script.
- [ ] **DST off-by-one in the cycle model (minor).** `buildFlowRuns` splits runs with `current - previous > DAY_MS` over local-midnight timestamps, and `dayDiff` divides a local-midnight delta by a fixed 24h. On a 23h/25h daylight-saving day this can wrongly split a continuous period run or shift a day count by one, nudging the estimated phase. Rare, low-impact. Origin: `packages/domain/cycles/models.ts` (`buildFlowRuns`, `dayDiff`).

Found in the Beta 2 build (2026-07-23):

- [x] **Can see other users' data without being friends / without consent.** A new account saw everyone's posts in the feed. Root cause: `posts_select_all` RLS was `using (auth.role() = 'authenticated')` — any signed-in user could read every post. (`cycle_events` / `cycle_snapshots` were already friend-scoped; only `posts` leaked.) _(Fixed: migration `20260724193000_posts-friends-only-select.sql` replaces it with `posts_select_own_or_friends` — own posts + any **accepted friend's** posts (`friend_requests.status = 'accepted'`, either direction). Posts use this looser friendship gate deliberately; the sensitive cycle rows keep the stricter mutual-sharing gate. Server-side, so it applies on `supabase db push` / running the SQL, no rebuild. Demo seed rows were separately removed by the cleanup script.)_
- [x] **Can't dismiss the keyboard** after typing in "what's on your mind" (post composer). Need tap-to-dismiss / a Done affordance / KeyboardAvoidingView fix. _(Fixed: feed drag-to-dismiss + Done return key.)_
- [x] **Boop / heart button states on your *own* post are backwards.** Boop buttons on self should look **disabled** (they don't/shouldn't work). The heart button is the opposite — it looks disabled on self but actually works, and shouldn't. Fix the enabled/disabled states so self-actions that don't apply look disabled. _(Fixed: heart disabled on self; both boop & heart use the disabled color on self.)_
- [x] **Selected mood inside "+ more" isn't shown outside "+ more".** When you pick a mood that lives under "+ more", it should also surface outside "+ more" (it's selected and will send). _(Fixed: selected moods are always added to the quick mood row.)_
- [ ] **Phase shows "unknown" despite Apple Health being synced earlier.** Unsure if a corrupted snapshot row or a real bug. Also: add a **"connected to Apple Health"** flag/wording somewhere so users know sync status.
- [ ] **Accepting a friend request may not result in a visible friendship — re-verify.** Krati accepted Lukas's request but they didn't show as friends. The accept path now looks correct (`respondToFriendRequest` updates status *and* calls `ensure_friend_sharing`; `loadFriends` self-heals sharing rows on every load), so this is most likely **stale data** — Lukas's account was **soft-deleted** before the hard-delete fix and still lingers in friend lists (see TODO "Purge pre-fix soft-deleted accounts"). Re-test with two live accounts before digging into the code path.
- [x] **New account floods the feed with backdated period posts.** On first HealthKit sync, every historical menstrual-flow sample in the 180-day lookback was auto-posted as a backdated `menstrual_flow` event. _(Fixed: `selectAutoPostedPeriodSamples` now takes a cutoff and `syncHealthData` only posts samples on/after the account-creation time from `session.createdAt`. Existing sessions pick `createdAt` up automatically on next app launch — no manual re-login.)_
- [x] **Deleting an account leaves data behind / errors with "Could not delete account right now."** The `delete-account` edge function **soft-deleted** the auth user (`deleteUser(uid, true)`) — the auth row stayed, so *no* cascade fired and app data survived; it also never cleared the non-cascading tables (`posts`, `post_reactions`, `event_reactions`, `boops`). _(Fixed: the edge function now best-effort-clears those non-cascading tables, then **hard-deletes** the auth user so cascades fire. **Deployed as `delete-account` v4.** Pre-fix soft-deleted accounts swept via the cleanup script.)_
